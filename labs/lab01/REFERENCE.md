# Ledger: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

Ledger хранит записи о движении денег. Он не изменяет баланс `Account` и не выполняет повторное списание.

`LedgerEntry(entry_id, transaction_id, account_id, amount: Money, entry_type)` — неизменяемая запись с положительной суммой. Направление задаётся `DEBIT` или `CREDIT`.

| Метод | Результат |
|---|---|
| `LedgerEntry.signed_amount() -> Decimal` | Отрицательная сумма для `DEBIT`, положительная для `CREDIT`. |
| `LedgerService.record(entry) -> LedgerEntry` | Сохраняет запись в готовом хранилище. |
| `entries_for_transaction(transaction_id) -> tuple[LedgerEntry, ...]` | Возвращает записи операции в порядке добавления. |
| `signed_total(account_id, currency) -> Decimal` | Считает итог счёта в указанной валюте. Для пустой выборки — `0`. |

Валюты в итогах не смешиваются. `entry_id` должен быть уникальным: даже идентичный повтор вызывает `DUPLICATE_ENTRY`. Готовое хранилище не позволяет заменить существующую запись.

Общий интерфейс дополнительных правил — `PostingRule.check(entry) -> CheckResult`. Начальные реализации — `AllowedEntryTypeRule(types)` и `MaximumEntryAmountRule(maximum)`. Положительность суммы и уникальность записи действуют независимо от списка правил. `Money`, перечисления, поиск и исключения уже реализованы.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
