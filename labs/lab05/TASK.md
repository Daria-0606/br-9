# ЛР5. Правила и хранилище как зависимости

Вариант: **Ledger**.

## Что дано

Сервис игнорирует `rules`, а список записей ошибочно оказывается общим у разных экземпляров. Основной метод `LedgerService.record()` также нужно реализовать; готовые проверки объектов и зависимостей не переписывайте.

## Задание

### Шаг 1. Сохраните зависимости и настройте сборку

В `LedgerService(repository, rules)` сохраняйте правила как `tuple`. В `build_service()` создавайте отдельное хранилище для каждого нового сервиса.

Уникальность ID и запись должны оставаться в готовом хранилище, а не в отключаемом правиле. Если одно хранилище передано двум сервисам явно, оно остаётся общим.

### Шаг 2. Реализуйте `LedgerService.record()`

До добавления проверьте уникальность `entry_id` готовой `ensure_new_entry()`, затем правила по порядку. Отказ превращается в `DomainError(result.code)`. Единственная запись в хранилище выполняется после всех проверок.

### Шаг 3. Проверьте отказ и следующий вызов

Контрольный исполнитель сначала выбрасывает `DomainError("TEMPORARY")`, затем успешно работает. Первый вызов не повторяется автоматически и не меняет данные; второй использует того же исполнителя. `TEMPORARY` — код учебной проверки, не новая ветка бизнес-логики. Отсутствие зависимости проверяйте через `is None`, а не её истинность.

### Шаг 4. Обязательная практическая часть

В `LedgerService` реализуйте `entries_for_account(account_id)` для выборки записей счёта в исходном порядке. `transaction_summary(transaction_id, code)` возвращает словарь `debit`, `credit`, `net` (`Decimal`) для одной операции и валюты; `net = credit - debit`. Чтение не должно создавать записи.

## Примеры и границы

- Контрольный отказ `ENTRY_TEST_DENIED` не создаёт запись.
- Пустые правила не разрешают повтор ID.
- Разные хранилища независимы; изменение исходного списка правил не влияет на сервис.
- Исключение правила оставляет журнал прежним.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
